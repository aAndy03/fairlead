## Purpose

A Rust workspace, `sync-stack`, with seven crates and a Tauri-style desktop shell. The example shows folder-based scopes (Rust module paths are aliases only), a deep managerial folder, the backend ladder and its rank checks, Cargo features kept apart from environments, a generated file declared at its generator input, and a tombstone for a removed engine.

Tags follow D-06 and D-38: `[0.1]`, `[0.2]`, `[0.3]`. Where a line needs two milestones, the first tags its syntax and the second its check. The open questions of the first draft are resolved in the last section.

```toml
# sync-stack/Cargo.toml (not fairlead's file; membership is read, never written)
[workspace]
members = ["crates/sync-core", "crates/sync-transport", "crates/sync-engines",
           "crates/sync-pipelines", "crates/sync-services", "crates/sync-derive",
           "crates/desktop-host"]
default-members = ["crates/desktop-host"]   # default scope when check or context gets no path
```

Seven folders are managerial: root, core, transport, engines, pipelines, edge-conflicts and host. `sync-services`, `sync-derive`, `edge/` and the TS file resolve upward (D-11). `sync-core` has a folder for one reason: a waiver needs an owner that CODEOWNERS covers (Q-EXRS-1). The `integrity/`, `handshake/` and `diff/` containers need no folder. Containment is folder structure, so no directive restates it (D-20).

Membership is read from `[workspace] members` in `Cargo.toml` as an oracle. Fairlead runs no cargo command and never edits a manifest (R-SCOPE-016, R-CHK-004). Where a declaration and the manifest disagree the declaration wins; a member with no scope yields only the `SCOPE-ELIGIBLE` hint.

## Root control and child identity

```toml
# sync-stack/fairlead/control.toml
[fairlead]                                  # frozen header, parsed first (D-33)
edition = 1
root    = true                           # root marker; nearest wins on lookup (D-31)
scope   = "root"
marker  = "fairlead"

[settings]
folder        = "fairlead"
fairlead-version = "0.1.0"
owners        = ["@platform", "@core", "@pipelines", "@host"]   # owners is a root-only list in 0.1, so every ovr owner is listed here (D-51, R-AGT-028)
purpose       = "sync-stack: Rust engines behind a Tauri shell."

[comments]                               # .proto is not in the built-in leader table (R-SYN-006)
".proto" = "//"

[kinds.port]                             # user-defined kinds; root-only vocabulary (D-02, R-HIER-001)
title  = "port"
shape  = "code"
layers = ["backend.primitive"]           # ladder binding [0.3]
[kinds.eng]
title  = "engine"
shape  = "code"
layers = ["backend.engine"]
[kinds.brg]                              # bridges (30 R-HIER-060)
title = "bridge"
shape = "either"
```

Kinds `fn`, `adapter`, `pipe`, `svc`, `cmd` and `wire` are declared the same way, with a `layers` value from the backend ladder.

```toml
[policies]                               # override policy per key pattern (D-02)
"rules.*"             = "sealed"         # rules are sealed by default
[policies.waiver]
budget   = 25
approval = "required"                    # every effective waiver needs fairlead approve

[policies."cargo.dep-version"]           # field-level policy (R-SYN-053): members may add features, not version or path
target = "cargo"
fields = ["dependencies.*.version", "dependencies.*.path"]
policy = "sealed"

[rules.hier-rank]                        # tunes HN-H007, hier.rank [0.3]
why = "use and Cargo edges point to the same or a lower rank"

[rules.env-leakage]                      # tunes HN-E001, the env-gate violation [0.2] (21 R-ENV-022)
why = "an item that reaches env E may not use an item whose env set excludes E"

[rules.primitive-io]                     # pattern rule (R-CHK-005): primitives do no I/O
check    = "pattern"
forbid   = "std::(fs|io|net)::"
msg      = "I/O belongs in an adapter (rank 1)"
glob     = ["crates/sync-core/src/**"]
sev      = "error"
stage    = "enforce"
waivable = true                          # needs-exception (D-02)
why      = "primitives stay free of I/O"

[rules.maturity-gap]                     # [0.2] rule.maturity-gap (21 R-ENV-020)
waivable = true                          # needs-exception; stable units may not depend on beta
why      = "a stable unit may not depend on a beta unit"

[layers.backend]                         # ranks [0.3]; preset from `fairlead new ladder backend`
primitive = 0
adapter   = 1
engine    = 2
pipeline  = 3
service   = 4
shell     = 5

[env]                                    # [0.2] root-owned, in order (21)
order = ["dev", "staging", "prod"]

[maturity]                               # [0.2] user words mapped to integer ranks (21)
alpha  = 0
beta   = 1
stable = 2

[bind]                                   # [0.2] env to real gate; existence checked, cfg never evaluated (21 R-ENV-030, R-ENV-035)
dev = "feature:dev-probe"                # Cargo features are never env; this maps one feature to one env
```

```toml
# sync-stack/crates/sync-engines/fairlead/control.toml
[fairlead]
scope = "engines"                        # stored identity (D-11); a child carries identity and local facts only in 0.1
```

Child control files carry identity and local facts in 0.1. Policy and vocabulary are root-only and sealed (D-02). A child that declares either becomes an escalation proposal to the root (`fairlead new escalation`, a `[[req]]` table).

## Directive lines

Grammar: `// fairlead: <verb> <id> [key=value ...]`. Only the six verbs exist. Only `//` line comments carry directives here; `///` and `//!` never do (D-18). rustc ignores non-doc comments, so `fairlead check` is the only validator of directive text. A bare ID resolves through the scope chain; `core:` and `engines:` name sibling scopes. Module paths never appear in an ID (D-27). The `.proto` file carries `//` directives through its `[comments]` entry. A unit's layer is `<ladder>.<layer>`, and no rank number appears in a unit (R-HIER-003).

### crates/sync-core/src/progress.rs [0.1; layer= 0.3]

```fairlead
// fairlead: def port.progress-sink layer=backend.primitive
```

### crates/sync-core/src/digest.rs [0.1 def and ovr; layer= 0.3]

```fairlead
// fairlead: def fn.digest layer=backend.primitive
// fairlead: ovr rule.primitive-io why="streams file bytes; adapter split deferred" owner=@core exp=2027-06-30
```

The `ovr` is needs-exception: effective once approved, with reason, owner and expiry. Without an approval `check` reports HN-X002, and the waived pattern finding returns as HN-U001 (R-CHK-025, R-CHK-060).

```fairlead
// fairlead: def pipe.sync-now layer=backend.pipeline

// fairlead: use engines:eng.diff-v2
// fairlead: ovr rule.maturity-gap why="diff_v2 is beta; pipeline stays stable until it promotes" owner=@pipelines until=1.8.0
```

The pipeline is stable and uses a beta engine. That breaks the gap rule, which is waivable. The waiver is recorded in the pipeline scope, which owns it. Its version expiry (`until=1.8.0`) needs seals [0.2]; a date form (`exp=`) would be [0.1].

### crates/desktop-host/src/commands/sync.rs [0.1 def and use; 0.3 bridges]

```fairlead
// fairlead: def cmd.sync-now layer=backend.shell
// fairlead: use pipelines:pipe.sync-now
// fairlead: def brg.sync-now proto=tauri-command dir="ts->rs" wire=sync_now ver=2 params=force:bool home=root ts="desktop-ui/src/sync.ts#syncNow" rs="crates/desktop-host/src/commands/sync.rs#sync_now"
// fairlead: def brg.progress-events proto=tauri-event dir="rs->ts" wire=sync_progress ver=1 implements=core:port.progress-sink ts="desktop-ui/src/events.ts#onSyncProgress" rs="crates/desktop-host/src/commands/sync.rs#emit_progress"
```

The shell implements a rank-0 port. That is an upward runtime flow, so it is declared as a bridge with `implements=` and no `reaches=`, which R-HIER-065 exempts from flow and rank checks (D-20), not as a plain `use`. `home=root` is the nearest common ancestor of the two ends (R-SCOPE-017).

### desktop-ui/src/sync.ts [0.3]

```fairlead
// fairlead: def brg.sync-now side=ts ver=2
// fairlead: use brg.sync-now pin=2
```

Presence on both sides, the wire literal and the version pin are checks (R-HIER-062, R-HIER-063; D-29). `params=` is presence-checked only; payload field equality is out of scope.

### Lifecycle record (tombstone) [0.2]

Before removal, `diff/legacy_diff.rs` carried `// fairlead: flag replace eng.legacy-diff to=eng.diff-v2 target=1.6.0`. A `#[deprecated]` attribute mirrors the flag, and `check` cross-checks the two, with the flag authoritative (R-LC-010). Removal writes a `[[tomb]]` record into the scope folder (R-LC-020; D-32). Its `by` field is the permanent `replaced-by` alias that a reference to the old ID resolves through (R-LC-011, D-50):

```toml
# sync-stack/crates/sync-engines/fairlead/tombstones/2026.toml
[[tomb]]
id      = "eng.legacy-diff"
removed = "1.6.0"
by      = "eng.diff-v2"
why     = "v1 diff; quadratic on 100k-line files; replaced (ADR-014)"
paths   = ["crates/sync-engines/src/diff/legacy_diff.rs"]   # for re-introduction matching (R-LC-033)
```

The ID stays reserved. Tombstones are kept forever (D-24, D-39).

## What this example shows

1. The folder is the scope. Module paths are aliases, so `#[path]` and `mod.rs` layouts do not move a unit between scopes (D-27).
2. Containers need no folder. The deep `edge/conflicts/` folder is a scope, and its parent `edge/` is not (D-11).
3. Membership is read from `Cargo.toml`, and fairlead never edits it. Cargo edges are checked as use edges, so a `core` to `transport` edge fails `hier.rank` even though it compiles [0.3].
4. Core directive work (`def`, `use`, `ovr`, waivers, `check`, `context`) is [0.1]. Environments, maturity, tombstones and version expiry (`until=`) are [0.2]; date expiry (`exp=`) is [0.1]. Ranks and the `implements=` bridge key are [0.3].
5. Cargo features and environments are separate axes. `[bind]` checks that `dev-probe` exists and never evaluates `cfg` (D-16).
6. Generated items are declared at the generator input, not at `OUT_DIR` (D-35).
7. A removed engine leaves a tombstone. Restoring its file re-triggers HN-D003.
8. Directive text is data. Only `fairlead check` validates it, because rustc ignores non-doc comments.
9. A waiver needs an owner handle, and an owner handle is listed in `owners`. A folder-less crate resolves to root, so `sync-core` got a folder.

Inheritance here follows [scopes](10-scopes-and-inheritance.md): open keys take the nearest scope; list keys append with `+=` (D-12); needs-exception keys change only through `ovr`; sealed keys and vocabulary are root-only (D-02).

## Resolved questions

- Q-EXRS-1 (resolved 2026-10-09): option (b). A crate that holds an `ovr` gets a managerial folder, so CODEOWNERS covers the folder that holds the waiver (D-03, R-AGT-028); a folder-less crate resolves to root and its waivers are owned by root handles; see R-SCOPE-003, R-CHK-053.
- Q-EXRS-2 (resolved 2026-10-09): `edge.rs` beside `edge/` is the error SCOPE-AMBIG (HN-C014) where `edge/` is a scope with no `own` entry; that is a 0.2 rule (R-SCOPE-019), and this tree has no such pair, so 0.1 reports nothing here. fairlead errors rather than merging, as rustc rejects the pair. `#[path]` has no error rule: fairlead does not read module paths, and scope follows the folder (D-27, R-SCOPE-003).
- Q-EXRS-3 (resolved 2026-10-09): test code defaults to env `test` only when the root declares that word or an alias of it (R-ENV-036). This root declares dev, staging and prod, so a `def` inside `#[cfg(test)]` is HN-E002 (warn, 0.2). `tests/*.rs` are members of the scope that holds them, not units of their own (R-SCOPE-018), and count as test-only code by path.
- Q-EXRS-4 (resolved 2026-10-09): `exclude = ["fairlead/"]` in `[package]` keeps the managerial folder out of the published crate; a missing exclude is PKG-HINT (HN-M009, info, 0.3). A crates.io consumer has no parent scope, so no fairlead rule reaches it; see R-PORT-054.
- Q-EXRS-5 (resolved 2026-10-09): confirmed. Macro output is declared at its generator source with `def ... gen=<generator>` (D-35; R-FILE-054; 12 edge case 17), which keeps the items visible to fairlead; 0.1.
- Q-EXRS-6 (resolved 2026-10-09): `params=` is a list of `name:type` words (D-51(7); 12 R-SYN-007). D-29 declares params, not structs, and only presence is checked; see R-HIER-063 [0.3].
- Q-EXRS-7 (resolved 2026-10-09): accepted limit. fairlead reads declared edges and never resolves features (D-16, R-ENV-030), so a dependent that enables `dev-probe` in a prod build is not detected; the limit is stated in reports and holds in 0.2 and 0.3.
