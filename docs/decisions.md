# Decision log (ADR-style, draft)

> Status: draft · Applies to: alpha 0.1.0 and the 0.2/0.3 milestones it plans for
> Product name `fairlead`, managerial folder `fairlead/`, directive marker `fairlead:` (D-58; the first working name was `harna`). The diagnostic-code prefix `HN-` is fixed and does not follow the name (R-CHK-042).
> A decision here overrides any conflicting statement in a chapter. As of 2026-10-09 every entry is owner-approved, including those formerly marked (inferred) (see D-46).

## Owner-approved
- **D-01 Wedge.** Lead with per-key inheritance + explicit override policy + expiring waivers + exception ledger. Drift reports and token budgets are table stakes (prior art: Archkeel, Archgate).
- **D-02 Override policy per key** (declared at the root). `open`: nearest scope wins. `needs-exception`: a child may override with a declared `ovr` carrying reason, owner and expiry; the override is effective AND recorded in the ledger. `sealed`: an override is inert until an ancestor grants it with an authored `allow`. Rules are `sealed` by default (children may only tighten); a rule marked `waivable` is `needs-exception`. Vocabulary keys (layer ranks, env/maturity slots, ID namespace, policy kinds) are root-only sealed; a child attempt becomes an escalation proposal to the ancestor.
- **D-03 Authority.** Floor rules compiled into the binary (cannot be waived); mandatory CODEOWNERS review of the managerial folder; `fairlead approve` records an approval so agents cannot self-approve. Git protects recovery, not review.
- **D-04 Styles.** Authored CSS is the source of truth for values; fairlead holds the token contract and a derived index and never merges file contents. Per-kind option to generate instead. Third-party-owned files (shadcn, heroui CLI output) belong to the *vendor-owned* file class; variants live in fairlead-owned wrapper units. `foreign` regions mark text written by other tools.
- **D-05 Format.** TOML for everything fairlead reads (control file, frontmatter delimited by `+++`, declarations). Markdown bodies for docs. No YAML (no maintained serde crate; serde_yaml archived, serde_yml has RUSTSEC-2025-0068).
- **D-06 Milestones.** Docs specify the whole model, every rule tagged by milestone. **0.1** = nested scopes, inheritance, `ovr`/`allow`, `def`/`use`, `check`, `context`, `init`, `new`, `explain`, `sync`, `approve`, baseline. **0.2** = seal, versions, environments, maturity, lifecycle/graveyard, editions/upgrade, git integration, docs-first coverage. **0.3** = layer ranks/hierarchy, reachability, variation protocol, portability/attach/detach, retention/compaction, TS<->Rust bridge. 0.1 exit criterion: a controlled test (about 20 tasks) showing agents change behaviour after reading `context`, plus measurable success criteria (see 60-roadmap).
- **D-07 Docs location.** Specification lives in `docs/` of this repo; the docs are the truth the human reviewer reads.

## Converged across agents (owner-approved 2026-10-09, see D-46)
- **D-10 Resolution.** Authored intent is resolved at read time down the scope chain and never copied. Only generated and reference files are written to disk. Facts roll up (registries, exception ledger counts, summaries) only at `seal` (0.2); in 0.1 the only generated files are the baseline and the scope index shards.
- **D-11 Scopes.** A managerial folder is eligible, not mandatory, for any folder; a folder without one resolves to its nearest ancestor scope (lazy creation, promotion, demotion). Scope identity is a STORED id in the managerial folder, not the path. The codebase root is a fixed marker (root managerial folder whose control file has `root = true`); root is never discovered by searching upward from the cwd. An unparseable control file makes `check` fail closed. Demoting or deleting a scope leaves a tombstone.
- **D-12 Shadowing.** A child redefining an inherited ID without `ovr` is an error. Override semantics per field: replace by default, explicit append marker for lists.
- **D-13 No per-file version headers.** Versions are tracked per scope and per ID'd contract item; file-level history is derived from git (`fairlead explain` reports a virtual file version). New docs get an immutable once-only stamp.
- **D-14 Seal (0.2).** Sealed version = highest `versions/N.md`; open version = sealed + 1; both derived, not stored. `seal` is all-or-nothing and writes the version file last (the commit point). Fairlead never commits unless `--commit`. Conflicts in generated files are resolved by regenerating them (no custom merge driver). Draft doc IDs are random; ordinals are assigned at seal, per scope. Seal runs on the integration line/CI by default; any branch allowed for solo work with collision repair. Global version is independent of Cargo/npm versions, with an optional mirror check. Exception expiry is version-based; date-based expiry is opt-in with `--as-of`.
- **D-15 Docs-first (0.2).** Check verifies path coverage (each changed file covered by a change doc), not temporal order. Severity ramps observe -> warn -> enforce, warn by default; per-scope opt-in to error; rolling `chore` docs and `exempt` globs; ordering enforced only by optional hooks.
- **D-16 Environments, maturity, lifecycle (0.2).** Three orthogonal axes with user-defined words mapped onto ordered canonical slots, root-owned. Cargo features/cfg and TS env flags are cross-checked for existence, never evaluated. Lifecycle: deprecate/replace/edit/remove with since/target versions; tombstones live in the scope folder; removed IDs are reserved forever; graveyard keeps rejected features with a fingerprint to catch re-introduction under a new ID. Owner authority is unauthenticated without signed commits, so rejection records rely on D-03.
- **D-17 Editions (0.2).** An edition is a byte-stable contract for grammar and generated output; new rules ship off within an edition. Unknown directive class = error, unknown key = warning, `!` marks a must-understand directive. One edition per codebase root; a sealed sub-root may carry its own.
- **D-18 Syntax.** Directives are COMMENTS (`// fairlead: ...`, `# fairlead: ...`, `/* fairlead: ... */`), never attributes, never doc comments (`///`, `//!`). Six source verbs: `def`, `use`, `ovr`, `flag`, `env`, `end`. `meta` and `note` are not source-line classes. IDs are `[scope:]kind.name`, path-independent. Kinds are user-defined in the control file. Directive text is DATA, never instructions to an agent.
- **D-19 File classes.** authored, generated, reference, vendor-owned, and append-only ledger (hash-chained, for compacted history). Reference files may contain only meta and note lines. Hand-edited lines in generated files are flagged. Generated files are committed, deterministic, sorted, sharded per scope.
- **D-20 Hierarchy (0.3).** Layer ladders are user-defined with ranks; presets scaffolded by `fairlead new ladder` (UI: atom, molecule, organism, template, page + shell/chrome; backend: primitive, adapter, engine, pipeline, service, shell). Ranks compare only within one ladder; cross-ladder edges need an explicit `flow`. Containment (tree, exactly one container) is separate from `uses` (DAG). Coverage is an adoption ramp L0 (containers) to L3 (entries and traces), not totality. Entries have kinds (export, test, registered). Audit verdicts: orphan (no container), stale AND dormant (unreachable and untouched). `uses` edges are comments (`// fairlead: use <id>`) aggregated upward; fairlead greps for the declared `sym=` in the consumer as evidence; an import extractor may feed the same graph later. Upward runtime flows use a port unit plus an `implements` bridge.
- **D-21 Variation protocol (0.3).** Every reusable unit has an ID and a home scope with visibility `subtree|public`. A variation request has four outcomes: use an existing axis, request a variant, wrap locally (expiring interim wrapper), or reject to a permanent adapter. A request is mandatory for primitive variations and becomes a doc-first change in the home scope. Hardcoded style tokens are detected by declared token values plus a property context (`applies=`), not by raw value matching.
- **D-22 Portability (0.3).** A root mounted inside a bigger codebase is a sealed sub-root with its own edition, opened only by explicit `adopt`. A lock is digest-only by default, full snapshot only for scopes declared `portable`. Doc IDs are namespaced by scope. A doc contradiction is a declared `contradicts` on an ID'd claim.
- **D-23 Context.** Output format is the terse `ID k=v` line (about 63% smaller than verbose YAML in S4's estimate) for both generated files and `fairlead context`. Tiers L0 index, L1 scope card, L2 detail, L3 archive. Merkle digests; `--since <version>` deltas; `--budget N` priority packing; BM25 task matching (later). Inherited rules are deduplicated so ancestors are not re-sent.
- **D-24 Retention (0.3).** Compaction runs inside `seal` using the seal's recorded timestamp, never the wall clock. Authored `sum:`/`out:` fields are mandatory at creation (fairlead has no LLM). TTL by version, not calendar: hot = open + last 3, warm = 8 versions; decisions, graveyard and tombstones are kept forever.
- **D-25 CLI.** Small fixed verb set; variety comes from syntax and user-defined kinds. Verbs: `init`, `check`, `sync`, `new`, `move`, `context` (absorbs status), `explain`, `seal` (absorbs compact), `upgrade`, `approve`. Whether `approve` folds into `new` is an open question.
- **D-26 No background processes.** Fairlead runs only while a command runs. Explicit foreground tools only.
- **D-27 Platform.** Written in Rust; analyses any text repo. 0.1 is AST-free (directive/comment/frontmatter extraction plus file tree); import-graph extraction (tree-sitter/syn) is later. `ignore` crate with `require_git(false)` and `git_global(false)`; git2 for git access (gix is pre-1.0); avoid bincode (discontinued). MSRV floor 1.88. Scope is folder-based; Rust module paths are aliases only. Generated or macro-produced items are declared at their generator source with a `gen` line.
- **D-28 Rollout safety.** Baseline files let a new rule land in a legacy repo; severity ramps observe -> warn -> enforce; waivers expire; waiver sprawl is reported.
- **D-29 Bridge (0.3).** TS<->Rust bridges declare params (not structs). 0.1/0.3 text checks: presence on both sides, wire literal, version pin. Payload field equality needs a parser or generator and is out of scope.
- **D-30 Name.** The first working name was `harna`; candidates verified unclaimed on crates.io were fairlead (preferred), gusset, lashing. The rename must be cheap: marker and folder name come from config. Superseded by D-58.

## Reconciliation decisions (resolve conflicts between drafted chapters; these amend the entries above)
- **D-31 Root lookup (amends D-11).** Order: `--root`, then `FAIRLEAD_ROOT`, then an upward search from the cwd that accepts ONLY a managerial folder whose control file has `root = true` (ordinary managerial folders are ignored; the nearest `root = true` wins, so a mounted sub-root stops the search). The search never invents a root. No root found = error, never a guess. Non-VCS trees work the same way.
- **D-32 Format split (amends D-05).** Everything AUTHORED that fairlead reads is TOML (control file, frontmatter delimited by `+++`, approvals, allow grants). GENERATED files and `fairlead context` output use the terse `ID k=v` line format (D-23). Directive carriers: `//`, `#`, `/* */` in code; `<!-- fairlead: ... -->` HTML comments in Markdown bodies; TOML frontmatter keys for doc-level metadata (e.g. doc-level `use`).
- **D-33 Control-file header and edition pin (resolves edition-pin question).** The control file `fairlead/control.toml` begins with a `[fairlead]` table (keys: `edition`, `root`, `scope`, `marker`) whose schema is FROZEN across all editions and is parsed in a first lenient pass before the rest of the file. No separate pin file.
- **D-34 Allow grants and approvals.** `allow` is not a seventh verb. A grant is a `[[allow]]` table in the granting ancestor's `control.toml`. Human approvals of exceptions/rejections are `[[approval]]` tables in `fairlead/approvals.toml`, written by `fairlead approve` (terminal-gated, not authentication; real review rests on CODEOWNERS per D-03). A tightening `ovr` on a field with a root-ordered scale takes effect without an `allow`; any loosening needs an `allow` or a `waivable` rule.
- **D-35 Foreign regions.** A region written by another tool is declared with `def foreign.<name>` closed by `end`. No dedicated verb. Generated items are declared with a `gen=` key on `def` (no separate `gen` line).
- **D-36 Reference files (amends D-19).** Reference files carry only a machine-readable header (class, fairlead version, edition, content hash) and prose; they contain no directives. Hand-edited lines in generated files are flagged.
- **D-37 Expiry (amends D-14).** In 0.1, `ovr` expiry is date-based (`exp=YYYY-MM-DD`) and `check` takes `--as-of` for determinism. From 0.2, version-based expiry (`until=<version>`) is the default; dates remain allowed.
- **D-38 Milestone placement (amends D-06).** `move` is 0.2 (0.1 relies on `sync` re-resolving membership, since IDs are path-independent). The baseline is written by `sync --baseline`; `check` is read-only. Hook installation is offered by `init`, never default-on. Within 0.1, implementation order is root-only first, then nested scopes; the spec covers both.
- **D-39 Retention clock (amends D-24).** TTL is version-based with a calendar floor (an item is never compacted before a minimum age, default 90 days). `out:` is filled when the item is closed, not at creation (`sum:` stays mandatory at creation). The hash-chained ledger uses periodic checkpoints so purging old detail never forces re-chaining of finalised years.
- **D-40 Registry declarations.** Units, containers, entries and bridges are declared with `def` directives, in code comments next to the symbol, or in `<!-- fairlead: ... -->` blocks in Markdown registry docs. `use` comments and the `sym=` evidence grep are best-effort; rank, orphan and stale verdicts are lower bounds until an import extractor exists, and reports say so.
- **D-42 Version format (amends D-14).** The global version is MAJOR.MINOR.PATCH, as in the owner's example (1.0.2) — not a bare integer. The sealed version is the highest `versions/<MAJOR.MINOR.PATCH>.md`; the open version is derived from the declared impact of the change docs since the last seal (breaking -> major, feature -> minor, fix/chore -> patch), highest wins. `until=<version>` takes this format. While MAJOR is 0 the same mapping applies shifted one level down (breaking -> minor). A once-only `created = "<version>"` key on new docs is identity, not a counter.
- **D-43 Literal-leak check in 0.1.** The check that finds hardcoded values where a declared token exists (the owner's original style-token example) IS in 0.1, using declared token values plus a property context (`applies=`); it is the 0.1 proof of the wedge. `check --changed` (changed files only) is 0.1.
- **D-45 Edition format.** The edition is an integer (`edition = 1`) in the `[fairlead]` header, not a year: a year implies a release cadence that cannot be promised. D-14's "versions/N.md, sealed + 1" wording is superseded by D-42 (MAJOR.MINOR.PATCH, impact-derived open version).
- **D-44 Exit-code addendum (extends D-41).** 5 = internal error or cannot-determine (e.g. unreadable git state when a command needs it). Defined only in 15-cli.md.
- **D-41 Exit codes.** Defined only in 15-cli.md: 0 ok, 1 findings at enforce severity, 2 usage/config error, 3 stale generated files (check), 4 refused by policy or authority (approve/adopt/escalation). Other chapters cite 15-cli.md and do not redefine codes.

## Acceptance decisions (2026-10-09)
- **D-46 Acceptance of open questions and inferred decisions.** The owner approved all inferred decisions (D-10 to D-45) and accepted every open question, both in the register ([70-open-questions](70-open-questions.md)) and at the end of each chapter, by the leaning stated there. Rules: (1) a question with a stated leaning is resolved as that leaning; (2) a leaning that conflicts with a D-xx decision is superseded by the D-xx decision, and the question is resolved as "superseded by D-xx"; (3) a question with no leaning ("Open") is resolved by the maintainer to the option most consistent with the decisions, recorded with its reason; (4) resolved questions move into the normative text of the owning chapter as numbered rules and remain listed as one-line resolved records, never as open items; (5) new questions that arise later are added as open and need owner acceptance. - **D-47 Name.** The target product name was `fairlead`, to be applied after a trademark check. Superseded by D-58.
- **D-48 Git access split (amends D-27).** Reading repository state (status, diff, history, rename detection) uses the git2 library. Actions that must run hooks or sign (`seal --commit`, `seal --tag`) and the signature checks of `check --ci` (`git verify-commit`, `git verify-tag`) run the user's `git` executable. No other verb commits, stages or pushes (D-14).
- **D-49 One key per concept (extends D-37).** `ovr` expiry is `exp=<date>` (0.1) or `until=<version>` (0.2+). `flag` targets use `target=<version>`; `flag` never takes `until=`. Chapters that wrote `until=` on `flag` are corrected.
- **D-50 ID rename, hashing, manifests (reconciliation).** (1) `move --id` is not part of 0.1 to 0.3; renaming or merging an ID uses `replaced-by` plus a tombstone alias (Q-LIFE-2, Q-SYN-4); the alias is stored in the tombstone, which is permanent, and a reference through an alias is reported until it is updated. (2) The content hash is blake3 everywhere (D-27); sha256 appears nowhere. (3) Fairlead reads no YAML: manifest parsing in 0.1 is Cargo TOML only (Q-TOOL-2); `pnpm-workspace.yaml` and `cargo metadata` are not used. (4) `fairlead-version` is a pin: a binary older than the pin or on another edition is refused per 15 R-CLI-005; a newer binary on the same edition proceeds with an info line.
- **D-51 Reconciliation from the worked examples.** (1) Chapter 13 defines HN-R004 (alias or removed-ID reference), gives the deprecated or replaced-ID reference warning (R-LC-008) its own code, and gives pattern-rule findings (`check = "pattern"`) their own code family; defaults: removed-ID reference is an error (HN-D003), deprecated-ID reference warns until the due version and is an error from it (HN-R006). (2) Contract-declared token derivations are checked from 0.1 (code HN-T005, [0.1]); graph-based derivation detection is a separate code, [0.2]. (3) A mismatch between the two ends of a bridge wire literal gets its own code in 13 ([0.3]), not a reuse of the missing-end code. (4) In 0.1 `owners` is a root-only list; from 0.2 a declaring scope may add owners for its subtree; chapters 10, 12, 13, 40 say so. (5) The maturity-gap rule has the legal ID `rule.maturity-gap` (chapter 21). (6) Field-level policy form: `[policies."<policy-id>"]` with a `fields = [...]` key (chapter 12). (7) Bridge `params` is a list of `name:type` words (chapter 12 R-SYN-007). (8) A change doc's draft `def` does not satisfy a `use`: a rule in chapter 20, cited by 13. (9) The story changes the examples made (bridge home at root, fullstack Year 4 seal 3.0.0, subtree-wide grants) are accepted.
- **D-52 Writer locks across worktrees.** `.fairlead/lock` is a per-worktree advisory lock held only while a writing command runs (`init`, `sync`, `new`, `approve`, `upgrade`; exit 4 on a second writer, 15 R-CLI-008). `seal`, `move` and `upgrade` additionally take a lock in the git common directory so that two worktrees cannot run them at the same time (Q-GIT-4; 23 R-GIT-073). Chapters 11, 15, 23 and 32 say so.
- **D-53 Path to 1.0.** The v1 API is the CLI surface, the directive grammar per edition, and the output formats (R-ARCH-003). It is frozen at the end of 0.3, when all three milestones are specified and built. Releases 0.4 to 0.9 close the gaps found after that freeze, without breaking the frozen surface except through an edition (D-17, D-45). 1.0 follows when the 0.4 to 0.9 gap list is empty. Gaps still open in the specification until then are expected, not defects.
- **D-54 Spec amendments from the 0.1 contract.** (1) Global flag `--threads N` and env `FAIRLEAD_THREADS` set the worker count (default: physical cores); added to the flag table in 15-cli.md. (2) `[eligibility]` control-file table with `min-lines` (default 5) and `min-files` (default 3) feeds scope-eligibility hints (10 R-SCOPE-011; 12 schema index). - **D-55 Generated headers carry no binary version (follows D-17).** Generated-file and baseline headers carry the edition only (`# scope <id> edition=<e> body=<hash>`, `# baseline edition=<e> body=<hash>`); the binary version is never stamped into a generated file, so a binary upgrade within an edition never makes a file stale. Reference files (D-36) may keep a version. Amends 11 R-FILE-003, 13 R-CHK-030/R-CHK-023 and the C-17 header of the 0.1 contract.
- **D-56 Absent scope exits 5 (follows D-44).** A scope absent from the working tree or a sparse checkout makes `check` exit 5 (cannot determine); an unresolved scope (unparseable control file) stays exit 2. Amends 13 R-CHK-057, 23 R-GIT-007, 15 R-CLI-003.
