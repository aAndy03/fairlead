# Agent runbook: evidence gathered by AI agents (0.2 and 0.3)

> Decision [D-59](../decisions.md): from 0.2, the evidence steps that 60-roadmap 4.2 and 4.3 assign to people run as AI-agent protocols. This file defines the shared rules and one protocol per step. The phase plans ([0.2/p7-quality-exit.md](0.2/p7-quality-exit.md), [0.3/p7-quality-freeze.md](0.3/p7-quality-freeze.md)) point here.

## Shared rules

1. **Two roles, never mixed.**
   - The **subject agent** does the work being measured: it writes code, writes directives, or adopts the tool.
   - The **reviewer agent** judges results: it labels, classifies, or reviews.

   A reviewer never sees which arm, run or model produced what it judges (opaque IDs, as in `ablation-score`). The agent that builds a fixture or writes the prompts is neither a subject nor a reviewer of that protocol.
2. **Fresh session per sample.** Use one `opencode run` call per sample, without `-c` or `-s`. No memory or project instructions carry over: run in an empty working directory with no `AGENTS.md` or `CLAUDE.md` unless the protocol places one.
3. **Isolation from the spec.** Subject sessions run in a copy of the fixture outside this repository. They must not be able to read `docs/`, the plans or the source. For an arm that may see `fairlead/`, give it only that fixture's folder.
4. **Fixed and recorded settings.**
   - Model, set by the owner on 2026-10-10: `opencode-go/muse-spark-1.3-contributor` (Muse Spark 1.3 Contributor, opencode Go plan), for subject and reviewer runs alike, always in separate sessions. A different model needs a new dated entry here, and runs made with different models are never pooled.
   - Record the model ID, the opencode version, the date, the commit hash and the run-order seed in the result file.
5. **Mechanical scoring wherever possible.** `cargo xtask` scorers count. Agents judge only what a scorer cannot (labels, classifications, reviews), and against a written rubric that is included in the reviewer's prompt.
6. **Results.** Write each run to `docs/plans/<milestone>/results/<date>-<protocol>.md`:
   - the settings;
   - the raw counts;
   - the verdict against the threshold;
   - the threats noticed.

   Raw transcripts stay outside the repository; keep only their hashes.
7. **Agents never approve.** `fairlead approve` refuses non-TTY and `CI` sessions on purpose (R-AGT-026). A protocol that needs an approval stops and asks the owner, who runs one command. Tagging a release is also the owner's.
8. **Honesty of claims.** Agent-run evidence is labelled "agent-run" wherever it is cited (R-VIS-005). A threshold missed is reported as missed.

## Runner

Each protocol uses one PowerShell runner pattern, generated by a task of the phase plan as `xtask/agent/<protocol>.ps1`:

```powershell
# one sample: fresh session, prompt file, answer captured as text
$Model = 'opencode-go/muse-spark-1.3-contributor'
opencode run -m $Model --format json --file $Context (Get-Content $PromptFile -Raw) > $OutJson
```

The runner reads a seeded, shuffled list of samples. It writes every answer under an opaque ID and keeps the private map (`map.csv`) in a separate folder that the reviewer step never receives.

## Steps that stay with the owner

| Step | Why |
|---|---|
| `fairlead approve` for waivers, upgrades and adopts | the product refuses agents (R-AGT-026, D-03) |
| Tagging `v0.2.0` and `v0.3.0` | publishing is an outward act |
| Edition, tree-sitter and MCP decisions (0.3 master Q-1 to Q-3) | the recommended default applies unless the owner says otherwise; recorded in the errata when a phase starts |
