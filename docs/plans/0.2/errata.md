# 0.2 errata

Deviations from the 0.2 plans, in the order they were made. The chapters and decisions.md win over the plans; the plans are not edited by executors.

- E2-1: P1-T1. `ACTIVE_MILESTONE = M02` and `PENDING_0_2` (40 codes, with a second test that fails when a listed code becomes asserted, so the list only shrinks). The workspace version stays `0.1.0` until the 0.2 release: the `check` header carries the binary version, so a `-dev` bump mid-milestone would churn every golden. Edition-1 byte stability is `tests/editions.rs` (`r_edn_051__...`): every golden that `sync` accepts must regenerate its committed `gen/` files byte for byte (CRLF checkouts compared after line-ending normalisation, R-GIT-013), instead of a copied `tests/editions/1/` tree. Two 0.1 tests that used `HN-V001` as their "inactive code" example now use `HN-H001` (0.3).
- E2-2 (owner, 2026-10-10): agent-run protocols use `opencode-go/muse-spark-1.3-contributor` (agent-runbook, shared rule 4).
- E2-3: P1-T2, P1-T3. `version.rs`: `Version` (strict `MAJOR.MINOR.PATCH`), `Impact`, `bump`, `VersionLine`, `derive_line`, `mirror_divergence`. With no pending doc, `O` is `S` bumped by `fix`, so `O` is always ahead of `S`; the chapter does not say what `O` is when nothing is pending. Spec gap: R-VER-004 says `check` SHOULD warn on mirror divergence, but chapter 13 has no code for it; the text is computed and waits for an owner-assigned code (proposed `HN-V017 H-VER-MIRROR`, warn).
- E2-4: v0.1.0 released (owner request): tag `v0.1.0`, GitHub release with three binaries and `blake3sums.txt`, and `fairlead-syntax`, `fairlead-core`, `fairlead` 0.1.0 published to crates.io from a clean worktree of the tag.
- E2-5: P1-T4. `docs.rs` (change-doc model: `DraftId`, `Status`, `ChangeDoc`, `parse_change_doc`, `collect_change_docs`, `readiness_problems`, `slug`) and `new change "<title>" [--field impact=..] [--field covers=..]`, planned through `pipeline::plan_new` (it needs the version line; `write::new_plan` refuses `change` directly). Change docs live in `<scope>/<folder>/docs/changes/d-<draft>-<slug>.md`; the chapters fix the filename but not the folder. Change-doc kinds: change, chore, mechanical, bulk, revert, retarget, early-removal, revive, upgrade. The 40 random bits come from the standard library's OS-seeded `RandomState` (no clock, no new crate). Not yet: the `[version]` control table (`start` is fixed at 0.1.0 until it is parsed), the check-side `H-DOC-EMPTY` (HN-V009) for an incomplete `ready` doc, and resolution of `d-<draft>` in doc-reference keys (R-VER-049); they land with the seal planner (P1-T8) and the refs work (P3-T7).
- E2-6: P1-T5. Ordinals (`docs::assign_ordinals`, per scope and kind, ordered by `created` compared as versions, then draft ID), the alias map `gen/alias` (`d-<draft> kind=<k> ord=<nnnn>`, written by `sync` only for scopes that hold a sealed doc, so 0.1 trees are unchanged), and the `versions` built-in: `H-ID-COLLISION` (HN-V006, same draft ID with a different content hash; identical copies are not reported), `H-ORD-DUP` (HN-V007), `H-DOC-EMPTY` (HN-V009, incomplete `ready` doc; also used for a change doc whose frontmatter is unusable, which chapter 13 gives no code of its own). An ordinal's scope is the doc's `scope` key. Deferred: `new --reid` (rename the later doc and rewrite references) lands with `seal --reseal` (P1-T13), which shares the rewrite.
- E2-7: P1-T6. `hist.rs` (module name chosen to avoid `registry::ledger`, the 0.1 exception ledger): year-file parse and render, `record_digest` (8 base32 of blake3 over the normalised record text without ` d=`), `checkpoint_digest` (previous checkpoint digest or header `prev`, then the record digests since), `append_version`, `finalise`, `verify` and `verify_chain`. Record lines after the last checkpoint count as a break: in 0.2 only seal appends, always with a checkpoint. Ledger files are read into `Facts::ledgers`, are no longer scanned for directives (no comment syntax, like fairlead's generated files, E-45), and breaks are `HN-G003` in the `versions` check. `sync` never touches them: the generated set holds no ledger-class path.
